# 本地运行日志

CLI、GUI 与 MCP 共用一套本地 JSON Lines 日志，便于定位安装、下载、版本切换、项目环境和更新失败。
日志不会自动上传，也不会混入命令的 JSON、shell 脚本或 MCP 标准输出。

## 查看与导出

```bash
vsm logs                          # 最近 100 条，按记录顺序显示
vsm logs --tail 200 --level error  # 最近 200 条错误
vsm logs --json                   # 目录、记录级别、文件信息和日志
vsm logs path                     # 日志目录
vsm logs diagnose java            # 在出问题的原终端记录版本与命令顺序
vsm logs export vsm-report.jsonl   # 导出全部保留日志到新文件
vsm logs clear                    # 只清理日志
vsm help logs
```

GUI 左侧底部点击「日志」，可按最低级别筛选、刷新、导出和清理；清理前需点击确认。
导出使用系统文件对话框，不会覆盖已有文件，请选择新文件名。
即使项目配置或安装目录配置损坏，仍可使用日志入口。

默认位置是 `~/.vsm/logs`，设置 `VSM_HOME` 时使用 `VSM_HOME/logs`。
项目 `local` / `docker` 隔离不会改变此位置，各入口可以一起诊断。
主文件为 `vsm.jsonl`，达到 2 MiB 时轮换为 `.1`、`.2`、`.3`，总计最多约 8 MiB。
多个 CLI 进程与 GUI 使用系统文件锁协调轮换和写入；进程异常退出后锁自动释放。
日志不可写或暂时被占用时不改变原命令的结果；查看、导出、清理失败会明确报错。

## 记录级别

在启动 CLI、GUI 或 MCP 服务前设置 `VSM_LOG_LEVEL`，支持 `debug` / `info` / `warn` / `error` / `off`，默认 `info`。

```powershell
$env:VSM_LOG_LEVEL = "debug"
vsm list-all python
vsm logs --tail 200
```

```bash
VSM_LOG_LEVEL=debug vsm list-all python
```

`info` 记录操作开始、结束、耗时；`warn` 记录下载重试、网络错误和版本探测失败；`error` 记录操作失败。
`debug` 额外记录 HTTP 状态及成功版本探测；每次提示符触发的 `env` 成功调用仅在调试级别记录。
筛选不会开启未记录的调试信息。`off` 停止新增日志，已有日志仍可查看和清理。
帮助、版本查询以及 CLI 日志查看、导出、清理不记录自身，避免反复查看日志产生新日志。`logs diagnose` 会显式生成诊断；GUI 导出时补充当前 GUI 进程的快照。

## 日志内容

每条记录包含 UTC 时间、级别、组件、事件、进程 ID、VSM 版本，以及操作相关字段。
操作的开始、结束和核心步骤使用 `operation_id` 关联；cmd 初始化的前后记录通过 `helper_session` 关联。`scope` 明确区分 GUI 进程、受控测试 cmd、实际初始化会话和手动诊断，避免把测试结果当成其它终端已经切换。
GUI 与 `vsm logs` 文本输出会按当前电脑时区显示时间，并标明 `+08:00` 等偏移；JSON 和导出文件保留 UTC，便于跨机器排查。
例如 `2026-10-19T12:47:39.506233Z` 中 `Z` 表示 UTC，在中国时区显示为 `2026-10-19 20:47:39.506 +08:00`。旧日志也会按此规则显示，无需修改原文件。
不记录完整命令参数、环境变量转储、子进程输出或 MCP 请求/返回正文。
激活诊断只记录与切换相关的白名单：PATH 前 12 项、首个命中的程序、PATHEXT、数据/安装/配置目录、所选与有效版本、覆盖来源及 Java/Go HOME；手动诊断和 GUI 导出补充最多 16 个候选命令。AutoRun 记录读回匹配结果、类型和指纹，保留原设置但不把原始启动命令写入日志。
URL 用户名密码、完整查询字符串和片段、常见密码/令牌字段及已知密钥环境值会脱敏。
错误信息可能包含本地文件路径；分享导出文件前可检查相关路径。
Unix 上新建日志目录权限为 `0700`，文件为 `0600`；Windows 使用当前用户目录的继承 ACL。

## 排查 cmd 切换失败

更新配套 CLI 和 GUI 后，点击「激活 PATH」生成带诊断的初始化脚本，重现一次切换。日志会包含全局配置写入、入口生成、启动配置读回、两种 cmd 模式验证和运行时实际分派结果。初始化脚本执行时自动记录 PATH 调整前后，保持静默；日志失败不会改变激活结果。

如果问题发生在已经打开的 cmd，在原终端执行 `vsm logs diagnose java`，再导出日志。这个命令不执行语言程序、不修改环境，并检查日志实际写入；配置损坏时保留失败事件，日志级别不足或目录不可写时会明确提示。无需用户手填安装路径。

没有实际会话记录并不能单独证明启动配置没有执行，也可能是脚本未加载、CLI 不可用、日志关闭或写入失败。详细事件说明及判断方法见[已有运行时说明](system-runtimes.md#用详细日志定位切换失败)。
