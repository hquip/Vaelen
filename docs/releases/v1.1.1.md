# v1.1.1

新增 Docker / 原生数据库版本切换，修复全局版本激活、已有环境探测与日志时区显示。

## 数据库版本与实例

- 支持 PostgreSQL、MySQL、MariaDB、Redis、Valkey。CLI 使用 `vsm db`，GUI 左侧新增「数据库版本 / 实例」。
- Docker 从官方镜像拉取，显示分层下载进度，并记录镜像 ID；原生模式复用已安装、已纳管的完整服务端和客户端程序。
- 支持实例配置、启动、停止、切换、状态、日志、连接信息和客户端执行。每个实例、版本单独保存数据，切回时使用原来的数据。
- 运行中切换会重启服务；失败或取消时尝试恢复旧版本。停止实例保留数据。
- 实例仅监听本机，采用随机凭据；普通状态隐藏密码。通过进程创建信息、容器/卷标签和跨进程锁校验所有权，阻止卸载仍被使用的原生程序。
- 数据目录、卷或凭据丢失时明确报错，拒绝用空库替代。SQL 和客户端输出不写入操作日志。

```bash
vsm db use postgres 17-alpine --name dev --port 15432
vsm db start dev
vsm db exec dev -- -c "SELECT version()"
vsm db switch dev 18-alpine
vsm db list --json
vsm db stop dev
```

原生示例：`vsm adopt mysql --path <完整安装目录>`，再执行 `vsm db use mysql 8.4 --backend native --name local-mysql --port 13306`。

Docker 需要已启动的 Docker Desktop / Engine；原生需要对应平台的完整数据库发行包。Windows Redis / Valkey 推荐 Docker。**新版本使用独立数据，不自动迁移旧数据**；跨版本升级需另行备份、导入。普通 `vsm use` 与 PATH 切换不会重启数据库服务。

## 全局切换与终端激活

- 修复旧 shim 指向旧 CLI，以及 Windows 系统 PATH 排在用户 shims 之前导致的全局版本切换无效。
- GUI 校验配套 CLI，区分已保存的全局版本、项目/环境覆盖、VSM 解析结果和当前 GUI 进程实际命令来源，提供可复制的终端激活指令。
- `path-init` 补齐 PowerShell 启动 hook；保留自定义 prompt 与退出码。zsh / fish 在下次提示符刷新全局选择。
- 项目版本和环境变量仍优先于全局默认；已有终端请按 GUI 指引激活或重开终端。

## 已有环境与日志

- 修复按工具扫描时混入其它工具环境、重复扫描和纳管后显示不清的问题；支持显式重新扫描和手动添加安装目录/可执行文件。
- 识别已存在的 Conda Python 环境，分别纳管并保留原有包与前缀；相同 Python 版本可用不同标识区分，普通 Python 范围不会隐式选中 Conda。
- 修复 Maven 命令与根目录识别，从核心 JAR 读取版本，避免受 JAVA_HOME 和当前项目影响，兼容旧的 bin 目录链接。
- CLI / GUI 人类可读日志使用本地时间并标明时区；JSON 和导出保留 UTC。例如 `12:47Z` 在中国时区显示为 `20:47 +08:00`。
- 解决 [#19](https://github.com/hquip/Vaelen/issues/19)、[#20](https://github.com/hquip/Vaelen/issues/20)、[#21](https://github.com/hquip/Vaelen/issues/21)。

## 更新与验证

已有版本运行 `vsm update --gui`。Windows 手动更新时，CLI 改名为 `vsm.exe`，与 GUI 放在同一目录；macOS Universal 应用内置 CLI，支持 Intel / Apple Silicon，最低 macOS 12。

验证覆盖三系统测试及构建、macOS 应用实际启动、五种数据库的原生集成测试及 Docker 跨版本切换。Docker 验证包括 PostgreSQL 17→18、MySQL 8.0→8.4、MariaDB 10.11→11.4、Redis 7.2→7.4、Valkey 7.2→8；原生测试默认以两个独立标识复用同一安装，验证数据隔离与恢复。
