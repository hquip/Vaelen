# v1.1.12

修复环境切换与版本诊断的边界行为，完善插件刷新和异常更新恢复，并减少提示符和 GUI 的重复配置读取。包含 [Issue #38](https://github.com/hquip/Vaelen/issues/38) 的 fish PATH 修复，见 [PR #39](https://github.com/hquip/Vaelen/pull/39)。

## 修复与改进

- **fish 子 shell PATH**：基础 PATH 和目标 PATH 按路径列表导出；嵌套 fish 后仍能找到系统命令，保留目录中的空格。多个受管变量能正确恢复，子 shell 不改变父 shell 环境。
- **fish 刷新和配置目录**：切目录已完成环境刷新时，紧随其后的提示符不再重复调用 VSM；其它提示符继续感知同目录全局版本变化。shims 前置去重，不改写持久的 `fish_user_paths`；自动配置遵循绝对 `XDG_CONFIG_HOME`。
- **临时版本会话**：例如 `vsm shell java 21` 将选择记录在子进程环境中，启动钩子不再将其覆盖为全局版本。主命令缺失时提前报错；隔离项目使用 `vsm run`。
- **初始化失败恢复**：项目配置损坏时，`vsm env` 仍输出完整基础环境恢复脚本，返回非零退出码并在 stderr 说明原因。MCP 按显式 `--project` 初始化，不受无关 cwd 的损坏项目配置阻断。
- **Python venv 一致性**：shell 激活和执行共用只读完整性检查。已有 venv 缺少版本标记、配置或 Python 入口时停止切换，保留已有依赖；hook 不自动重装环境。
- **准确的版本上下文**：`context --check` 识别所选二进制或当前实例生成的完整 shim，核对目录、CLI、工具及脚本内容。正常 shim 不再误报未激活，旧提示符标签不覆盖已确认路径；其它实例、旧 CLI 和被改过的脚本仍会被拒绝。查询不执行运行时。
- **Unix 执行权限**：安装主命令必须是有执行权限的非空文件或有效链接。损坏安装不再被 `install` 当成可用而跳过，不自动更改外部安装权限。
- **插件刷新**：内置和外部插件分开保存。GUI 点击「刷新」会完整验证并替换外部集合，删除定义后不再保留旧插件；删除内置工具的覆盖定义后恢复内置实现。错误文件明确报错并保留上一套集合，并发读取不暴露半套更新。
- **更新锁恢复**：CLI/GUI 更新、macOS 应用更新和配套 CLI 准备共用系统文件锁，进程异常退出后自动释放。旧版残留空文件可复用；目录中保留 `.vsm-update.lock` 是正常现象，不代表仍有任务，不要在更新期间手动删除。
- **配置读取优化**：单次环境规划和 GUI 状态刷新共用配置及安装索引快照，下一次操作重新读取。本机每组 5 次、包含进程启动的 `vsm env bash` 中位耗时：浅目录约 160 → 27 ms，额外 8 层目录约 418 → 41 ms。实际收益随系统和项目变化。

## 更新方式

GUI 点击「检查 VSM 更新」，完成后重启；配套 CLI 会一起处理，无需单独下载。macOS `.app` 内置 CLI。

```bash
vsm update --gui
```

只用命令行时运行 `vsm update`。手动替换 Windows / Linux 文件时使用同版本 CLI 与 GUI。

fish 用户在健康的终端重新执行 `vsm activate fish | source`，或重新启动已配置自动激活的 fish。旧版若已经将多个 PATH 目录以空格合并，不能可靠区分目录内空格，请从正常父终端启动。自定义 fish 配置目录的用户可重新运行 `vsm path-init fish`。

本次升级仍由旧更新器启动；若旧版已被残留锁阻止更新，请先手动启动本版程序，再使用新版更新流程。其余新版修复随更新后的程序生效。
