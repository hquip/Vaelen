# v1.1.2

修复 Windows cmd 自动激活缺失，并自动检查各工具的命令入口。

- GUI 点击「激活 PATH」现在同时配置用户 PATH、cmd AutoRun 和 PowerShell 启动钩子，让 VSM shims 优先于系统已有的 Java、Node、Python 等程序。
- 自动读取已配置工具的版本、来源和安装位置，运行独立 cmd 激活验证并逐项显示结果，无需用户手填路径。缺失/损坏安装和工作目录中的同名程序会明确报错。
- 已通过 VSM shim 的同一 cmd，后续全局切换立即生效，不必重新激活或重开；已用真实 JDK 验证 17→21→17。
- 保留原有 cmd AutoRun 内容及注册表类型；重复设置幂等，配置被其它程序改动时拒绝静默覆盖。初始化脚本适配中文、空格路径。
- 提供已有 cmd 的一次性激活命令，以及「打开已激活 cmd」按钮；CLI `vsm path-init` 和 `vsm path-init cmd` 同步支持 cmd 自动配置。
- GUI 启动时的 PATH 不再被当成其它终端的实际状态；配套 CLI 版本检测区分启动失败、超时和版本不一致，增加首次启动的等待时间。

## 更新

GUI 点击「检查 VSM 更新」，或执行：

```bash
vsm update --gui
```

**更新后点击一次「激活 PATH」**，安装 cmd 自动启动配置。Windows 手动下载时，CLI 改名为 `vsm.exe`，与 GUI 放在同一目录；macOS Universal 应用内置 CLI。

已经通过 VSM 的终端可继续使用，切换后直接运行工具。从未加载 VSM 的已有 cmd，仍须执行一次弹窗中的 cmd 命令，或打开已激活终端；GUI 无法直接改写另一个进程的环境。项目版本和 `VSM_<TOOL>_VERSION` 仍优先于全局默认。

cmd `/D` 会跳过 AutoRun；`/V:ON` 请改用 `/V:OFF`。cmd 自动激活的数据目录不支持 `%` / `!`。保留原 AutoRun 的位置和撤销方法见 [Windows 激活说明](https://github.com/hquip/Vaelen/blob/v1.1.2/docs/system-runtimes.md#windows-全局切换与-cmd)。

验证包括三平台测试与构建、macOS 实际启动、真实 cmd 连续切换、通用工具检测、临时注册表中的配置保护，以及 Windows/macOS 界面交互和小窗口布局。
