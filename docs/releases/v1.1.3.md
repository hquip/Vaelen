# v1.1.3

修复 GUI 误选旧 CLI 导致无法切换版本，以及激活检查误报成功的问题。移除终端激活弹窗。

## CLI 配套与切换

- GUI 同时识别 `vsm.exe` 和 GitHub 下载的 `vsm-windows-amd64.exe` 等当前平台文件名，按版本选择。旧标准名副本不再遮住同目录的新 CLI，PATH 中的旧 CLI 也不会直接用于切换。
- 缺少匹配 CLI 时，从 GUI 对应的官方稳定 Release 下载，核对 SHA256、组件、平台和版本后，以官方文件名保存在 GUI 旁边。不覆盖其它位置或标准名的旧副本，程序目录需要可写。
- `vsm` 命令和语言 shim 指向同一份 CLI，避免旧的 PATH 副本重新生成旧 shim。
- GUI 设置全局版本前实际读取目标程序版本。数字安装标识与程序报告的版本不符时拒绝修改全局默认，避免显示“Java 17”却运行 Java 21。

## 执行验证与界面

- 激活验证实际执行未限定路径的工具命令，并与所选程序的版本输出比较；遵循 cmd 当前目录、PATH 和 PATHEXT 查找规则，不再仅凭 shim 文件路径判断成功。
- 日志记录所选版本、实际版本和 CLI 来源；损坏程序、错误 dispatcher、目录中的同名程序或 PATHEXT 跳过 `.cmd` 等情况会明确失败。
- 移除终端激活弹窗和“打开已激活 cmd”入口；按钮显示配置和组件下载进度，完成后只显示简短结果。版本来源与命令路径默认折叠。

## 更新

GUI 点击「检查 VSM 更新」，或执行：

```bash
vsm update --gui
```

Windows 手动下载时，将 GUI 与当前平台 CLI 放在同一目录，CLI 无需改掉官方文件名。**升级后点击一次「激活 PATH」**，更新通用命令入口；之后已通过 VSM 的同一 cmd 内，全局切换无需反复激活或重开。

从未加载 VSM 的已有终端不能由 GUI 直接改写环境，仍需加载一次初始化脚本；项目版本、环境覆盖仍优先于全局设置。使用方式与边界见 [Windows 激活说明](https://github.com/hquip/Vaelen/blob/v1.1.3/docs/system-runtimes.md#windows-全局切换与-cmd)。macOS Universal 应用内置 CLI，支持 Intel / Apple Silicon，最低 macOS 12。

## 验证

先在旧代码上复现 CLI 误选和错误版本被接受，再补回归测试。完整 race / vet、三平台 CI 与构建通过。

Windows 实际 Wails WebView2 测试同时保留旧 0.1.0 CLI 与未改名的新版 CLI，点击真实 GUI 后，同一个 cmd 中真实 JDK 17→21→8→17、Node 20→22→25→20 的输出均符合选择。测试使用临时 VSM_HOME，未修改原有语言安装或用户终端配置。
