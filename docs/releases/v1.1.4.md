# v1.1.4

为 VSM 自更新加入停滞重试、官方换路、并行分块与任务内续传，减少卡在 0 B 和断流后整包重下的问题。

## 下载行为

- 更新包连接或响应体连续 15 秒没有数据时中止当前请求，每个区间最多尝试三次。
- 有官方资产 ID 时交替尝试 GitHub 下载地址与官方 API；不自动使用第三方镜像。
- 8 MiB 以上资产使用 1 字节 Range 探测；支持时最多 4 连接下载，复用探测到的 CDN 地址，避免每个分块重复等待 GitHub 重定向。
- 分块断流后保留已收到的数据及已完成分块，只请求剩余字节。该续传限当前任务，不是退出程序后的断点缓存。
- 服务器不支持或不正确实现分块时回退单连接；服务器忽略续传区间、返回完整文件时明确重置相应进度。

## 进度与校验

- GUI / CLI 显示连接、保留数据重试、并发数、官方下载/API/CDN 和回退阶段。日志记录停滞、保留字节和分块回退。
- 严格检查 Content-Range、响应长度和完整官方 SHA256。JSON 元数据、异常区间、多余数据、损坏或取消均不能写入待替换文件。
- 所有组件下载、校验和程序验证完成后才替换；保留已有的失败回滚机制。

## Redis 探测与诊断

- `--version` 失败或未返回 Redis 版本时，尝试官方支持的只读 `-v` 参数；不使用会被当成配置文件的 `version` 子命令。
- 只接受 `Redis server v=...` 签名，避免把错误输出中的 Windows 或 jemalloc 版本误认成 Redis。
- 两次探测均失败时保留各自错误及程序输出，GUI 直接显示详情；日志记录实际探测路径。
- Windows 便携版 Redis 3.0.504 / 5.0.14.1 已验证文件、目录和 PATH 三种探测入口。Issue #26 的截图未包含失败详情，尚未复现该安装的具体原因，继续保持开放。

## 更新

```bash
vsm update --gui
```

GUI 也可点击「检查 VSM 更新」。**从旧版升级到本版的下载仍由旧更新器执行**；若旧版仍卡住，可先配置可用代理，或在本发布页手动下载对应的 CLI 与 GUI，放在同一目录。Windows CLI 可保留官方文件名；macOS Universal 应用内置 CLI。

分块和换路能减少无效等待与重复下载，实际吞吐仍取决于 GitHub、网络和代理。实网测试已观察到直连停滞以及 API 路径低速；不将这些优化视为固定倍数的加速保证。

## 验证

先用旧实现复现无响应连接不换路、断流后不续传，再验证修复。测试覆盖真实四连接并发、成功区间保留、响应体停滞、CDN 复用、Range 不支持回退、异常区间、错误 SHA256 和取消。完整本地 race / vet 与 Windows/macOS 小窗口交互通过；发布 CI 验证三平台测试与构建。
