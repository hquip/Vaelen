# v1.1.5

修复 GUI 全局切换时配套 CLI 下载进度不可见、其它操作被误报为“安装/纳管任务进行中”的问题。

## 问题原因

GUI 缺少同版本 CLI 时，设为全局和激活 PATH 都会自动从对应的 GitHub 官方 Release 下载组件。此前只有激活 PATH 入口会显示下载百分比；从全局切换进入同一流程时，后台下载不可见，而写锁仍按预期保护当前操作。本次日志确认的一次全局切换耗时约 131 秒，随后正常完成。

## 修复

- 底部增加持续显示的运行组件进度栏，两个入口共用，显示连接、下载字节、速度、重试、分块数与校验阶段。准备完成后自动继续原操作。
- 全局切换与激活 PATH 在操作期间暂时禁用；切换语言或刷新详情后仍保持进行中的状态，成功或失败后恢复。
- 通用忙碌提示改为“另一项操作正在进行”；配套 CLI 准备期间明确说明正在下载或校验，并引导查看进度。
- 新增 `gui · cli.prepare.started/completed/failed` 日志，记录耗时与真实失败原因。保留写锁，避免并发修改配置或程序。
- CLI、GUI、Windows 文件版本与 macOS 应用版本统一为 `v1.1.5`。

## 更新

```bash
vsm update --gui
```

也可在 GUI 点击「检查 VSM 更新」。Windows 手动下载时将同版本 CLI 与 GUI 放在同一目录，CLI 可保留官方文件名；macOS Universal 应用内置 CLI。

## 验证

回归测试覆盖延迟准备期间的并发操作，以及成功、失败和底层取消后的进度状态、原始错误与写锁释放。完整 GUI race 测试和 `go vet` 通过，Windows/macOS 720×520 界面点击验证覆盖全局切换进度、重试、重新渲染、失败恢复与再次操作。三平台 CI 和发布流程继续验证 CLI、GUI、真实 Redis 与数据库环境。
