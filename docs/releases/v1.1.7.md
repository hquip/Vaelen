# v1.1.7

修复 Issue #26 中 Redis 已输出 `Redis server v=5.0.14.1 ...`，仍被显示为「版本读取失败」的问题。

## 原因与修复

旧实现先等待版本探测进程退出。部分环境中 Redis 已打印完整版本，但探测命令未在 4 秒内完成；VSM 随后丢弃已有输出，并用 `-v` 重试，最终两次都显示超时。

- 只读系统检测和手动路径检查在超时后保留完整 Redis 服务端版本输出，不再因为进程退出延迟而清空版本，也不重复等待同样的备用参数。
- 只接受以换行结束、包含 Redis 服务端标识、版本、sha、malloc 和 bits 的完整输出行。截断版本、客户端输出和系统诊断中的数字均不作为有效结果。
- 超时仍会终止本次启动的探测进程；日志新增 `detect · redis.exit_timeout`，保留程序路径、参数与已读取版本。
- 正常结束但返回非零退出码仍报错；实际命令执行和激活验证仍要求进程正常完成。

## 更新

```bash
vsm update --gui
```

也可在 GUI 点击「检查 VSM 更新」。升级并重启后，点击「系统检测 → 重新检测」，或在 Redis 页点击「重新检测」。Windows 请同时更新 CLI 和 GUI 并放在同一目录；macOS 应用内置 CLI。

## 验证

先用旧实现复现截图中的两次「版本探测超时；Redis server v=5.0.14.1 ...」，再验证修复。回归覆盖输出后挂起、手动路径检查、执行验证仍拒绝超时、显式非零退出和不完整输出拒绝。真实 Windows Redis 3.0.504 / 5.0.14.1 探测继续通过；三平台 CI 验证 CLI、GUI 和数据库环境。
