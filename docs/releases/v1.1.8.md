# v1.1.8

修复一条已复现的 Windows 版本切换失败路径，并把原先短暂显示的「命令未经过 VSM」改为可查看、可重试的诊断结果。

## 修复与改进

- Windows 命令扩展名 `PATHEXT` 缺少 `.CMD` 时，cmd 会跳过 VSM 的入口，继续执行原来的 Java 等程序。初始化脚本现在自动补齐 `.CMD`，保留已有扩展名，支持大小写差异和重复加载；PATH 已正确配置时也会修复。
- 激活验证区分当前目录同名程序、VSM 入口被高优先级程序遮挡、入口缺失和运行失败，显示原因与下一步操作。不会自动移动或删除用户原程序。
- GUI 在页面中保留验证结果，支持重新验证、展开详情和复制诊断信息。部分工具失败时仍保留其它工具的结果，不再只显示短暂错误提示。
- 诊断详情与日志记录实际命中的命令、所选程序、实际版本、命令扩展名及错误分类，便于继续定位其它原因。

## 更新

```bash
vsm update --gui
```

也可在 GUI 点击「检查 VSM 更新」。Windows 同时更新 CLI 和 GUI；macOS 应用内置 CLI。升级并重启 GUI 后，点击「激活 PATH」重新验证。

已加载 VSM 的同一 cmd 可连续切换全局版本，无需在每次切换后重新激活。从未加载 VSM 的已有 cmd 仍需加载一次初始化脚本，见 [Windows 激活说明](../system-runtimes.md#windows-全局切换与-cmd)。GUI 的受控执行验证不代表它能够改写其它已运行终端的环境。

## 验证

使用真实 CLI 和独立运行程序复现 `.CMD` 缺失导致 Java 17 选择被绕过，再验证修复后同一 cmd 中 Java 17 → 21 → 17 连续切换。回归覆盖扩展名保留、大小写、重复加载、未设置扩展名、当前目录遮挡、入口目录遮挡、错误 shim 返回其它版本，以及 GUI 部分失败诊断保留。界面在 Windows/macOS 布局下验证重试、错误恢复和诊断复制；三平台 CI 构建 CLI、GUI，并验证 macOS 应用启动。

原来的错误提示可能对应多种原因；截图本身不足以断定所有用户均由 `.CMD` 缺失导致。本版同时提供具体命中路径与错误分类，供其余环境进一步定位。
