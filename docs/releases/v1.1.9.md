# v1.1.9

修复两条已复现的 Windows cmd 激活失败路径，新增详细日志，用于定位“全局版本已保存，但终端仍运行旧版本”。

## 修复与改进

- **兼容 cmd 延迟变量展开**：旧初始化脚本在 `/V:ON` 下直接退出；现支持 `/V:ON` 与 `/V:OFF`，保留调用者模式。验证同时检查两种模式，避免只在 `/V:OFF` 测试通过却漏掉真实失败。
- **保留原 PATH 内容**：修复旧脚本拼接带引号和 `&` 的 PATH 项时破坏环境的问题，保留字面 `!` 和已有命令扩展名，重复加载不累积 VSM 前缀。
- **准确显示切换结果**：GUI 区分“全局默认已保存”、当前有效版本及项目/环境变量覆盖；保留尚未重新验证的失败详情。激活结果提供按实际数据目录生成的 cmd 加载命令，可直接复制。
- **完整诊断链路**：记录全局配置写入、shim 生成、用户 PATH 写入、cmd 初始化脚本指纹、AutoRun 写入后读回结果、两种模式验证及最终启动的程序。操作编号串起核心步骤，初始化会话编号关联 PATH 调整前后。
- **原终端只读采集**：新增 `vsm logs diagnose [tool]`，记录当前终端继承的命令顺序和版本来源，不运行语言程序、不修改环境，并确认诊断实际写入。GUI 导出会补充 GUI 自身的状态快照。
- **日志可用性**：候选命令和 cmd 模式列表在保存、读取及导出后完整保留并逐项脱敏；自动初始化中的日志失败不阻断激活。沿用本地时间显示、敏感内容脱敏和自动轮换。

## 更新与排查

```bash
vsm update --gui
```

也可在 GUI 点击「检查 VSM 更新」。Windows 同时更新 CLI 与 GUI；macOS 应用内置 CLI。

**升级并重启 GUI 后，点击一次「激活 PATH」，重新生成修复后的初始化脚本。**已有 cmd 若仍运行旧版本，按界面提示在原 cmd 加载一次；已经通过 VSM 的终端，后续全局切换无需反复激活。

仍有问题时，在出现问题的原终端执行：

```bash
vsm logs diagnose java
vsm logs export vsm-diagnostics.jsonl
```

或从 GUI「日志 → 导出」导出。默认 `info` 级别即可；`VSM_LOG_LEVEL=off` 会关闭新记录。日志明确区分 GUI、受控 cmd、实际初始化会话和手动采集；受控验证通过不代表程序改写了其它已运行终端的环境。

日志只记录 PATH 前部、命令候选、必要 HOME/版本覆盖和配置路径，不记录完整环境、任意命令参数、子进程输出或原始 AutoRun 命令。日志保存在本地，详见[日志说明](https://github.com/hquip/Vaelen/blob/v1.1.9/docs/logging.md)。

## 验证

使用真实 CLI 与独立运行程序先复现 `/V:OFF` 通过、`/V:ON` 失败，再验证修复后同一 cmd 连续 Java 17 → 21 → 17 切换。覆盖 PATH 引号、`&`、字面 `!`、模式保持、重复加载、缺少 `.CMD`、单模式损坏拒绝、实际会话日志、列表脱敏往返，以及日志不可写/关闭时继续激活。本地完整 race 测试、`go vet` 和 Windows/macOS 布局下的界面操作验证通过；三平台 CI 验证 CLI、GUI、数据库及 macOS 应用实际启动。

这些是已复现并修复的源码缺陷；用户截图中的命令优先级问题仍可能存在其它触发条件。本版提供实际会话日志以继续定位。
