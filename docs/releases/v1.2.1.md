# v1.2.1

修复 Windows 首次打开 GUI 或运行安装脚本后，终端仍提示 **“vsm 不是内部或外部命令”** 的问题。

## 自动注册 VSM 命令

- 打开 Windows GUI 后自动查找、校验或下载同版本 CLI，建立全局 `vsm` 命令入口，加入用户 PATH 并配置 cmd 自动加载。无需先安装语言，也无需把 `vsm-windows-amd64.exe` 等官方文件名手动改名。
- Windows 安装脚本安装后自动注册，兼容旧 CLI 的初始化命令；成功后当前 PowerShell 可直接执行 `vsm`。
- 界面显示首次注册结果、失败原因和重试入口；缺少 CLI 时沿用下载、分块、速度和 SHA256 校验进度。日志中的 `command.setup` 记录注册过程。
- 重复注册不累积 PATH，保留已有变量引用、注册表字符串类型和 cmd 原启动命令。从 local / docker 项目启动或项目配置损坏时，仍只注册全局命令入口。

## 使用与边界

升级时请使用 GUI「检查 VSM 更新」或执行：

```bash
vsm update --gui
```

Windows 更新后重新启动 GUI，即会自动注册。新 cmd 自动加载；已经打开且从未加载过 VSM 的 cmd，可在原窗口执行界面提供的加载命令一次，随后继续使用同一终端。

也可以使用 CLI 完整路径只注册命令：

```powershell
& "C:\path\to\vsm.exe" path-init --command-only
```

自动注册处理全局命令入口；语言版本的完整激活与执行验证仍通过「激活 PATH」或 `vsm path-init` 完成。此功能不直接改写其它已运行终端的环境，不修改系统 PATH、PowerShell 执行策略或项目版本要求。cmd `/D` 会跳过启动钩子。

Windows、macOS、Linux 的 CLI 与 GUI 版本统一为 **v1.2.1**；macOS 提供 Intel / Apple Silicon 通用应用。本次自动注册改动用于 Windows。
