# v1.2.3

修复已激活的 PyCharm / Python venv 被全局解释器覆盖、pip 依赖装入错误环境，以及已复现的 Python 安装元数据限流失败。

## Python 与 pip 环境修复

- 普通 shell 提示符刷新、Python shim 和 `vsm which python` 尊重已激活的外部 `VIRTUAL_ENV`，不再把纳管的基础 Python 放到它前面。
- 正确保留虚拟环境的激活和退出状态，退出后恢复 VSM 选择，不会重新激活已退出的 venv。项目配置出错后恢复基础环境时，也保留有效的外部 venv。
- 新增 `pip` / `pip3` 命令入口，通过当前解释器的 `python -m pip` 执行，避免旧 pip 启动器内嵌的绝对路径指向其它 Python。
- 激活的 venv 缺少解释器或 pip 时明确失败，不回退到全局解释器安装依赖。Python / python3 别名和子进程退出码保持正确。
- 显式声明工具链的项目执行、锁定执行和 `local` 隔离项目仍按项目配置运行。

## 已有 venv 纳管

- Windows 正确识别 `Scripts/python.exe`；Unix 保留 venv 的环境根目录，不把指向基础解释器的符号链接当作同一环境。
- 相同 Python 版本的多个 venv 使用独立的 `venv-<名称>-<路径摘要>` 管理标识；支持手动添加环境根目录或解释器。
- 普通数字版本或 `latest` 不会自动选中携带独立依赖的 venv；注销纳管只删除链接，保留原环境和依赖。
- 日志记录实际分发的 Python 路径、虚拟环境和 pip 模块执行方式。

## Python 安装恢复与优化

- 安装元数据和官方摘要请求遇到代理出口 GitHub API 403/429 时，尝试官方 API 直连；校验值请求保持来自官方。
- 安装明确版本时，找到匹配发行包即停止读取无关历史发布；部分安装缓存不会截断完整版本目录。
- 补齐已有官方发行包的 Windows ARM64 平台匹配。

## 更新与使用

在 GUI 点击「检查 VSM 更新」，或执行：

```bash
vsm update --gui
```

GUI 更新会一并准备配套 CLI。更新并重启 GUI 后，点击一次「激活 PATH」或执行 `vsm reshim`，生成新的 pip 入口，再在项目终端重新激活 venv。

PyCharm 项目解释器请选择虚拟环境中的实际文件：Windows 为 `.venv\Scripts\python.exe`，Unix 为 `.venv/bin/python`。Windows `.cmd` shim 用于终端，不是 IDE 所需的原生解释器。

```bash
python -c "import sys; print(sys.executable); print(sys.prefix)"
python -m pip --version
```

路径应指向项目虚拟环境。此前误装入基础 Python 的依赖需依据项目清单在正确的 venv 中重新安装；本次修复不会自动搬迁或删除已有依赖。没有具体错误日志的安装失败仍需分别诊断，不能一概归因于 HTTP 403。

已使用真实 Python 3.10.9、3.12.16 验证环境隔离，并完成 3.12.16 官方包安装及 SHA256 校验。回归覆盖 cmd、PowerShell、Bash、zsh、fish 中的激活、刷新、安装依赖和退出流程。
